# Trace a concern into a tested design

TrustTrace asks how an organisation building an LLM-enabled system can show, step by step, why a design choice answers a stakeholder's trust concern, and where that evidence stops. It has two parts:

1. **An engineering case.** A typed metamodel and an authored logistics-compliance case connect eight stakeholder roles to 40 requirements, decision records, software components and executed test scenarios. A trace verifier fails on any dangling link.
2. **A feasibility pilot (B10).** Can a small local language model extract atomic obligations, with exact supporting evidence, from a text? Does a prompt guided by the metamodel do better than a naive one? The pilot ran on 17 October 2026 against labels the author wrote by hand.

**Python 3.12** · **Pydantic metamodel** · **Protocol frozen before collection** · **uv lockfile**

## Results

### B10 pilot: obligation extraction

Two local models (Qwen2.5-1.5B and Mistral-7B, both 4-bit), two prompt arms, 10 synthetic one- or two-sentence user stories, 3 seeds. Predictions are matched to the gold obligations by a rule fixed before any output existed, then checked against a blinded human audit of 30 pairs.

| Mistral-7B (Metal GPU, M1 Max) | guided | 1.00 | 0.91 | 0.88 | 0.95 | 0.63 |

- **Qwen2.5-1.5B**, guided minus naive macro F1: -0.010 (95% bootstrap CI -0.121 to +0.090); guided better on 3 of 10 texts, naive better on 3.
- **Mistral-7B**, guided minus naive macro F1: +0.050 (95% bootstrap CI +0.000 to +0.117); guided better on 2 of 10 texts, naive better on 0.

**Matcher audit.** On 30 blinded pairs the automatic matcher agreed with the author on 87% of items (Cohen's kappa 0.73). By the rule fixed before collection (kappa at least 0.6) the F1 values are treated as reliable for this pilot. Every pair the matcher accepted was judged the same obligation, but so were 27% of the near-misses it rejected, so the matcher is conservative and F1 probably understates recall. The 15/15 stratified sample describes these pairs, not matcher accuracy overall.

17 gold obligations were labelled by the author across 10 synthetic one- or two-sentence user stories; each model and arm ran 3 seeds per text (120 generations). F1 is per run, averaged over seeds within a text, then over texts.

### Engineering trace

All 16 must requirements trace to a valid source, decision record, component and passing requirement-marked scenario; 22 of 24 should requirements do too ([traceability report](results/derived/traceability.json)). Executed scenarios cover selective sharing, mandatory human review, citation membership, tenant-scoped retrieval and audit-chain verification ([scenario tests](tests/scenarios/test_boundaries.py)). Coverage of this synthetic case does not establish that a real ecosystem is trustworthy.

## Quick start

Use Python 3.12 and `uv` from the repository root:

```bash
make setup     # Sync the committed lockfile
make test      # Lint, format, strict typing, tests and integrity checks
make analyze   # Regenerate traces, pilot results, tables and report text
make report    # Build paper/report.pdf (needs a LaTeX installation)
```

`make analyze` loads no model: it rescores the committed generations in [`results/b10-pilot/raw/`](results/b10-pilot/raw/) against the gold labels in [`data/b10_pilot/gold.jsonl`](data/b10_pilot/gold.jsonl). Regenerating the model outputs themselves needs the pinned GGUF files and `scripts/b10_pilot_collect.py`; see [`docs/reproduce.md`](docs/reproduce.md).

## Limitations

- **Ten one- or two-sentence user stories**, written by the same project that wrote the guided prompt, are not a population. The pilot says nothing about legal text or a retrieval arm.
- **One annotator**, so there is no inter-annotator agreement. The audit checks the matcher against that annotator, not against a panel.
- **Different backends.** Qwen ran on a 2-thread cloud CPU and Mistral on the Mac's GPU after the cloud run was interrupted ([deviation](DEVIATIONS.md)). Backend changes sampled output: of 20 Mistral runs generated on both, 18 differ in raw output and 1 of 16 scorable runs changed F1 (`backend_check` in the [summary](results/derived/b10_pilot_summary.json)). Latencies are not comparable across models.
- **Matcher weights and threshold are assumptions**, not tuned values. The audit supports them (kappa 0.73) but shows the matcher is conservative, so F1 probably understates recall.
- The engineering case is authored, not elicited from practitioners, and specific ISO characteristic mappings remain unverified.

More in [`docs/limitations.md`](docs/limitations.md).
