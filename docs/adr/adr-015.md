# ADR-015: Persist state atomically and checkpoint the log to a separate anchor store

Status: accepted for the synthetic reference implementation. This is an architecture decision record (ADR).

## Context and decision drivers

ADR-004 verified the chain against a supplied anchor but kept everything in memory. A restart lost the review queue, and an attacker who controls the log also controls its anchor.

Requirements: TR-020, TR-033. Conflict: CONFLICT-04.

## Considered options

In-memory only; database with no anchor; atomic file persistence plus checkpoints written to a separate append-only file.

## Decision outcome

Review and audit state is written atomically and reloaded on start. Count and head checkpoints go to a separate anchor store. Verification uses the latest checkpoint, so a rewritten log fails.

## Consequences

A separate file on the same host is not an independent system. Production needs a different administrative domain or a transparency log.

## Reflection

Assumption: the anchor store is harder to tamper with than the log. An operator would object to running a second system. Possible bias: availability of the file-based design. Check: the test rewrites the whole log and confirms verification fails against the stored anchor.

The reflection subsection is our proposed adaptation, motivated by the Ethics-Aware DecidArch abstract linked in the source register. We have not validated this adaptation with architects.
