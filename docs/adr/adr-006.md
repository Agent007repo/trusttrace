# ADR-006: Grant access through purpose-bound, expiring delegations

Status: accepted for the synthetic reference implementation. This is an architecture decision record (ADR).

## Context and decision drivers

Partners need shipment data to coordinate, but a standing role grant (for example "all carriers may read shipments") gives every carrier every shipment for as long as the role exists. The authority role is the sharpest case: it needs access, but only for a documented legal purpose.

Requirements: TR-023, TR-024, TR-027. Conflict: CONFLICT-03.

## Considered options

Standing role-based access; per-shipment grants without expiry; per-shipment, purpose-named grants with expiry and grantor-only revocation.

## Decision outcome

Per-shipment, purpose-named grants with a timezone-aware expiry. Only the grantor revokes. Authority grants must name one of a fixed list of purposes. Every grant and revocation is an audit event.

## Consequences

Each new shipment needs a grant, which adds friction for high-volume forwarders. The purpose list for authorities is synthetic; a real one must come from legal analysis, not from us. Expiry uses the caller's clock, so clock skew between organisations is unaddressed.

## Reflection

Assumption: purpose strings can be agreed between organisations. A forwarder would object that per-shipment grants slow dispatch. Possible bias: anchoring on familiar OAuth-style scopes. Check: we tested the expiry, wrong-purpose and wrong-revoker paths explicitly rather than only the happy path.

The reflection subsection is our proposed adaptation, motivated by the Ethics-Aware DecidArch abstract linked in the source register. We have not validated this adaptation with architects.
