# ADR-010: Gate provider and version changes on evaluation and a recorded decision

Status: accepted for the synthetic reference implementation. This is an architecture decision record (ADR).

## Context and decision drivers

Replaceability is part of sovereignty: an organisation should be able to switch provider. But a swapped model can silently change behaviour that earlier tests validated.

Requirements: TR-019, TR-031, TR-032. Conflict: CONFLICT-06.

## Considered options

Swap freely behind an API; pin one provider permanently; allow replacement only with a passing contract evaluation and a recorded compatibility decision.

## Decision outcome

A model gateway refuses a replacement unless an evaluation record for that exact provider and version passed the output-contract tests and names a compatibility decision. The change is audited.

## Consequences

An output-contract test checks shape, not quality. A version bump of the same provider is treated like a provider change, which adds friction. Who signs the compatibility decision is an organisational question.

## Reflection

Assumption: contract tests catch the most damaging regressions. An operator under cost pressure would object to the extra step. Possible bias: overconfidence that a passing schema check implies behavioural equivalence. Check: the decision record must be non-empty, and we state in the limitations that quality evaluation is not included.

The reflection subsection is our proposed adaptation, motivated by the Ethics-Aware DecidArch abstract linked in the source register. We have not validated this adaptation with architects.
